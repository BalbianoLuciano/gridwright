# Gridwright

## What it is

An end-to-end layout pipeline: a Figma node goes in, and a component or view
comes out — built, visually verified and registered in the project's design
system. Driven from Claude Code.

**Guiding principle**: the design comes in as a node and leaves as a system.
Every run leaves the project with more resolved tokens, more registered
components and more verified surface. If a component turns out fine but
contributed nothing to the system, the run failed.

## The spec rules

`specs/001-pipeline.md` defines the 10 laws, the 15 stages and the development
phases. **Read it before writing code.** Any implementation decision that
contradicts a law in there is wrong.

The four that get forgotten most:

- **Law 1** — the workflow is state on disk (`.gridwright/runs/<id>/state.json`),
  not text in a prompt. The CLI orchestrates, Claude acts.
- **Law 2** — the raw Figma tree never reaches the LLM. It always goes through
  the IR.
- **Law 5** — nothing that mutates the project is written without approval:
  `plan`, `tokens` and `golden` are human gates.
- **Law 10** — the secret does not pass through the model. **Claude never runs
  `gw auth login`**: when the Figma token is missing, stop and ask the person to
  run `! gw auth login` in their terminal. A token that went through the
  transcript is compromised.

## Language

**This repo is written in English** — code, comments, docs, tests, commit
messages, CLI output. It ships as a public npm package and a Claude Code plugin,
so its audience is not only Spanish speakers.

This overrides the Spanish-comment convention used in the other repos. What
carries over is the part that matters: **comments explain the *why*, not the
what.** The good ones say what broke before.

## How Luciano works

Established from working with him on the portfolio, on `autofill` and on the
Dmeter products.

**Spec before code.** Spec-driven development, and not as a slogan: the
portfolio has a `specs/001-interaction-language.md` with four laws governing
every interaction on the site, written before implementing. For something this
size the first deliverable is a spec, not a scaffold.

**Business rules are data, not code.** A pattern he repeats across products: the
effort-per-activity table, the per-age-bracket limits, the schema for each
category. If something can change without touching the algorithm, it ships as
data.

**Tests that earn their keep.** Not coverage for coverage's sake: tests against
the real thing. Hornero has 248 against an actual Postgres. `autofill` has 127,
several traced from real forms that broke.

**No margins between siblings.** Flex or grid with `gap`. A hard rule in his UI
projects.

**Nothing ships or publishes on its own.** A cross-cutting design principle at
Dmeter: *the system generates, the person decides.*
